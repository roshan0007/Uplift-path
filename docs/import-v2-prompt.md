# Uplift Path — Relume v2 import

The Relume design for this site has been substantially redesigned: new sections,
new components, new photography. Everything needed is in `designv2/` at the repo
root. Import it and rebuild the site on a new branch.

Read `CLAUDE.md` first, then `.claude/skills/uplift-path-design/readme.md`.

## What's in `designv2/`

Two artifacts, both from the same Relume revision:

1. **The Relume export** — the "export to Claude Code" download. React/JSX using
   `@/components/ui/*`, `relume-icons`, and `scheme-N` classes. **This is the
   source of every page section.**
2. **The design system** — generated by Claude Design from (1). Tokens,
   `globals.original.css`, `production.md` (component map), per-section
   screenshots, fonts, logo, images.

If a third folder is present — a plain **"export React"** download — it is
**reference only. Do not merge it.** It speaks Relume's v3 Tailwind preset
(`bg-background-primary`, `text-md`, `rb-*`), which Tailwind v4 cannot resolve at
all: no error, just silently unstyled. It was discarded in the previous import for
exactly this reason, and was also missing components. Use it only to recover a
component the Claude Code export drops.

Verify the two artifacts match before starting: the section list in the design
system's `production.md` should line up with the folders in the export. If they
disagree, they came from different Relume revisions — stop and say so.

## Known traps — every one of these cost time in the v1 import

**`globals.css` does not compile as shipped.** The export nests
`@layer theme { @media ... }` *inside* `@theme`, which Tailwind 4 rejects outright.
`app/globals.css` is derived from it with three fixes, marked `[1] [2] [3]` in the
current file's header: self-hosted fonts, that block lifted out, and an
`@theme inline` block. Re-derive with the same three fixes. Never hand-edit token
values.

**The `scheme-*` colour utilities are defined nowhere — not even in the export.**
`.scheme-1`...`.scheme-4` set `--color-scheme-*`, but Tailwind can't know those are
colours, so `bg-scheme-foreground` / `text-scheme-text` / `border-scheme-border`
generate *nothing* without an `@theme inline` block naming them. It must be
`inline`, or the values freeze instead of resolving per section. Symptom when
missing: every card borderless, every input transparent — silent, no error.

**Relume's exporter drops components.** It refused three last time (`Layout613`,
`Layout564`, `Layout615`) over an invalid nested `<img>`; they were recovered into
the design system's `missing-components/`. Check for that folder in the new
bundle, and cross-check the section count against `production.md`.

**Export bugs fixed in v1 — check whether they recur, and don't "restore" them:**
`features is not defined` (crashed `ai-consultation/layout-485` and both
`layout-486`s; fixed with a derived `FEATURE_COUNT`), `tansition-all` in
`ui/textarea.jsx`, `mb-8border-none` in `business-conusltation/layout-353`.

**Section folder names carry Relume's typos** (`business-conusltation`,
`advisory--services`) and the routes match them. If the new export fixes those
spellings, every one is a changed URL on a **live, indexed site** — each needs a
301. Static export means no middleware and no `next.config` redirects: the Worker
is static-assets-only with no `main` script, so use `public/_redirects`, and
verify it actually works on Workers Assets before relying on it.

**Never white text on the teal/green fill** — 1.96:1, fails WCAG AA.
`scheme-1`/`scheme-2` already encode the correct pairing via
`--color-scheme-btn-text`. Don't re-derive it by hand.

**Photography:** check whether the new images are real client photos or more
Relume stock. The v1 QA report flagged stock placeholders in the navbar mega-menu,
testimonial company logos, and a testimonial avatar. Flag any that remain — don't
silently ship them.

## Definition of done

- `pnpm build` passes clean.
- Every route renders and matches its design-system screenshot.
- No `imagedelivery.net` URL anywhere in the source.
- No unstyled section — spot-check one section per `scheme-N`: no transparent
  cards, no borderless inputs.
- 301s in place for every changed slug.
- Root contains only config; no loose reports.
- `master` untouched. Show the running site and wait for approval before merging.
